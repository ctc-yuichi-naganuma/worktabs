# 拡張と更新

[English](../extensions.md) | **日本語**

サイドバーの上端の歯車で、「設定 > 拡張」を開きます。更新があるときや更新に失敗したときは、サイドバーの更新のカードの「拡張と更新」からも開けます。表には、拡張ごとの入手元と版が出ます。Worktabs が使うのは、拡張自身のチャット欄と、拡張に付属する実行ファイルです。ターミナルでの代用や、別に更新する CLI ではありません。

設定と拡張の管理の画面は、Worktabs の表示言語に従います。操作のラベル、入手元の状態、ファイルを選ぶダイアログのタイトル、インポートの検証のエラーも同じです。拡張と製品の名前、版の番号、パス、対象プラットフォームの識別子は、元のままです。

## 入手元と更新の担当

| 拡張 | 既定の入手元 | 更新のしかた |
|---|---|---|
| Claude Code | 発行元が Open VSX に出したリリース | Worktabs で更新を確認して適用する |
| Codex | 利用者が用意したデスクトップの VS Code の拡張か VSIX | 入手元を更新してから、Worktabs で再インポートする |
| 設定で足したほかの拡張 | Open VSX（インポートしたものを除く） | Worktabs で更新を適用するか、記録した入手元から再インポートする |
| 言語パックと Worktabs の補助拡張 | Worktabs が管理する | code-server と、アプリの補助拡張の版に合わせる |

Claude には、デスクトップの VS Code は要りません。Anthropic は、[VS Code の派生版では Open VSX から入れる方法を案内しています](https://code.claude.com/docs/en/vs-code#install-the-extension)。インポートした拡張は、記録した入手元に固定し、Open VSX の更新の対象から外します。すでに入っている Codex はそのまま動きます。ただし Worktabs は、Codex の代わりとして Open VSX の古いリリースを入れたり勧めたりすることは、もうしません。

ブランチ名を考えるときも、選んだプロバイダーの、Worktabs で使用中の拡張の中にある実行ファイルを使います。Claude にも Codex にも、`PATH` に別に入れた CLI は要りません。考えるたびに、使用中の拡張の一覧を読み直します。このため、更新の適用、再インポート、拡張の復元をすると、次からは新しい実行ファイルを使います。実行ファイルのインストールと更新は、上の表の拡張の入手元に合わせます。

拡張か実行ファイルがないときは、worktree の追加のダイアログが、Worktabs での準備のしかたを案内します。Claude は、有効にしてタブを開くと入ります。Codex は、「設定 > 拡張」で、そのコンピューターのプラットフォームとアーキテクチャに合うものをインポートします。認証がないか期限が切れているときは、Worktabs のタブでそのプロバイダーのチャット欄を開いて、サインインします。WSL では、リポジトリと同じディストリのタブを使います。WSL の Linux 版の拡張とログインは、Windows とは別です。Worktabs は、Codex のログインを管理せず、その設定も書き換えません。

デスクトップからインポートした拡張は、ときどき VS Code を開いて、そちらで更新します。「VS Code を開く」はデスクトップのアプリを起動するだけで、Worktabs がその更新の機能を操作することはありません。Worktabs に戻って更新を確認し、手元の新しい版を適用します。確認するのは、記録したフォルダで使用中の版です。世の中で最新のリリースではありません。VSIX からインポートした拡張は、ときどき対応する新しいファイルを手に入れて、インポートします。デスクトップの VS Code には「Download VSIX」と「Download Specific Version VSIX」があります（[公式の手順](https://code.visualstudio.com/docs/configure/extensions/extension-marketplace#can-i-download-an-extension-directly-from-the-marketplace)）。

「公式ページ」は、拡張の公開ページをブラウザで開きます。Worktabs は、Microsoft Marketplace の API に問い合わせたり、そこからダウンロードしたりはしません。「設定した入手元に更新は見つかりませんでした」は、どこから見ても最新だという保証ではありません。使えないデスクトップの入手元と、VSIX の配布元の新しいリリースは確かめていないためです。`updateCheck` で、起動時の確認と、手元の入手元を 1 分ごとに見る動きを切り替えます。手動の確認は、いつでもできます。

## インポートと利用の許可

1. このコンピューターか、WSL 用の Linux のアーキテクチャを選びます。
2. 見つかったデスクトップの拡張、ほかの VS Code の拡張フォルダ、VSIX ファイルのどれかを選びます。見つけるときは、使用中の `extensions.json` の項目を読みます。VS Code Insiders と `VSCODE_EXTENSIONS` も読みますが、使われなくなった古いフォルダは読みません。
3. 発行元のライセンスと、code-server で使う許可を確かめます。利用の許可を確認して、「選択した拡張をインポート」を押します。

Worktabs は、ID、版、アーカイブの中のパス、プラットフォーム、必要な VS Code のエンジンの版、必要な拡張を検証します。依存する拡張は、先に入っているか、同じ回のインポートに含まれている必要があります。言語パックと補助拡張は、インポートで置き換えられません。ネイティブのバイナリも含めて、拡張の中身はすべてまとめて扱います。インポートできる大きさは、展開して 4 GiB、VSIX で 2 GiB までです。大きなデスクトップの拡張は、まとめるのに 1 分以上かかることがあります。Codex は、Windows と Linux のバイナリを含むので、1 GB を超えます。

コピーできることは、ほかのアプリで拡張を使ってよいという許可ではありません。Marketplace の利用の制限と、Microsoft の拡張の制限は、[VS Code の FAQ](https://code.visualstudio.com/docs/supporting/faq#extensions) にあります。発行元の規約も確かめてください。インポートできるからといって、Marketplace のどの拡張も code-server での利用が許され、code-server で動くとは限りません。

## 適用と復元

手元からインポートした拡張は、SHA-256 のハッシュを付けた、変更しないスナップショットとしてキャッシュします。更新は、Claude と Codex のターンが終わり、編集が保存されるのを待ってから、作業していないタブを再起動します。拡張の更新は Codex のプロキシを通らないことがあります。このため、Codex が起動したのに、そのプロキシがまだ知らせてきていないタブは、先に閉じる必要があります。そのタブは、サイドバーに名前が出ます。Worktabs が知らない Codex の状態は、作業中とみなします。待っている更新は、サイドバーで取り消せます。共有の拡張を変える前に、Worktabs は作業していないインスタンスを止め、新しく起動しないようにします。

インストールのあと、見えないところで手元の workbench を起動して、起動できることと、起動時に有効になると宣言している拡張を確かめます。インストールかこの確認に失敗すると、キャッシュしてある前の中身を入れ直し、新しく足したものは取り除きます。すべてのコマンド、ログインの流れ、チャットの応答までは確かめません。「以前のバージョンに戻す」は、キャッシュしてあるひとつ前のスナップショットを、ダウンロードせずに入れ直します。そのスナップショットの記録した入手元も、そのまま保ちます。記録には、拡張ごとにひとつ前のスナップショットを 1 つだけ残します。キャッシュを自動で片付ける機能は、まだありません。

## WSL

`linux-x64` か `linux-arm64` 向けに、合う Linux 版か、プラットフォームによらない（universal）拡張を、別にインポートします。Windows でインポートしたものを WSL に写すことはありません。準備したスナップショットは、対応するディストリで次にタブを起動したときに入ります。表に出るのは準備した版で、WSL に実際に入っていると確かめたものではありません。WSL での失敗では、まだスナップショットを自動で戻しません。残っている前のスナップショットには、「以前のバージョンに戻す」で戻せます。WSL で起動を確かめて失敗したらまとめて戻すことと、初めてインポートしたものを取り除くことは、まだこれからです。

Claude は、Windows の版に固定せず、Open VSX の Linux 版を使います。アプリが管理するほかの拡張は、できるものは Windows と同じ版にそろえます。

## 組み込みのギャラリー

`restrictExtensionGallery` の既定は `true` です。組み込みのギャラリーと、エディタの拡張の自動更新は使えません。アプリが管理するインストールは、これまでどおり Worktabs を通して Open VSX を使います。別の更新の経路が、インポートした拡張を知らないうちに置き換えないためです。

これは管理の方針で、セキュリティのためのサンドボックスではありません。手で VSIX を入れたり、ファイルを直接書き換えたりすれば、共有の拡張は変わります。`restrictExtensionGallery` を `false` にするのは、組み込みの Open VSX のギャラリーをあえて戻したいときだけにします。Microsoft Marketplace に向け直すことはありません。
