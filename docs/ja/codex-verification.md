# Codex の検証

[English](../codex-verification.md) | **日本語**

Codex への対応の受け入れの表です。スレッドの履歴と、最初のタスクの下書きも含みます。マスを合格にする前に、実際に動かした結果を記録します。単体テストとオフラインの拡張の材料では、サインインした公式の拡張での動きは確かめられません。

## 準備

1. 利用が許された Codex のデスクトップの拡張か VSIX を、「設定 > 拡張」からインポートします。コンピューターのプラットフォームとアーキテクチャに合わせます。WSL では、Linux 版をインポートし、対応するディストリでタブを開いて、Worktabs にそこへ入れさせます。
2. 「設定 > 一般」で「Codex」を有効にします。両方を一緒に使うときは、「Claude Code」も有効のままにします。新しいタブの既定のエージェントと、ブランチ名を考えるエージェントを選びます。[config.codex.example.json](../../config.codex.example.json) は、承認を手動にした、Codex だけの例です。
3. その環境で、Codex のチャット欄からサインインします。Worktabs は拡張に付属する実行ファイルを使うので、PATH に別の CLI は要りません。Windows と WSL では、拡張のインストールと認証が別です。
4. Worktabs のコミット、OS、アーキテクチャ、WSL のディストリとネットワークのモード、code-server の版、両方の拡張の版、プロバイダーの選択、認証の方法を記録します。認証情報や、認証の応答は添付しません。

## 記録した結果

2026-10-12 の時点で、今回の実装を macOS 26.5.2、Apple Silicon、Node 26.10.0、Electron 44.4.5、code-server 4.141.0、補助拡張 0.9.13 で確かめました。ソースから動かしたアプリは、ほかと切り離した一時的なデータフォルダと拡張フォルダを使いました。利用者がインストールしたアプリのデータは変えていません。サインインしての実行では、ソースのコミット `6ec63188d7c898eb428433dbdbaf82e12b867d4c` を、Codex 拡張 26.1007.21434、付属の CLI 0.162.0-alpha.17.2、パネルの切り替え用の Claude Code 拡張 2.1.296 で確かめました。

|---|---|---|---|
| Windows（ネイティブ）、公式の拡張 | メンテナーの判断で延期 | メンテナーの判断で延期 | メンテナーの判断で延期 |
| WSL、公式の拡張 | メンテナーの判断で延期 | メンテナーの判断で延期 | メンテナーの判断で延期 |
| macOS、公式の拡張 | サインインした Claude の回帰の確認はまだ | 下の移動と下書きの確認は合格。実際のターンはまだ | Codex の確認と、プロバイダーのパネルの切り替えは合格。Claude の認証と実際のターンはまだ |

Windows と WSL の実機での確認は、メンテナーの判断で延期し、エージェントによる今回の実装からは外しました。まだのマスは、あとで確かめるために、まだだとはっきり書いておきます。macOS での実行では、利用が許された Codex の認証を一時的なホームで使い回し、一時的な primary の最初の案内を済ませました。そして、一時的に作った本物のリポジトリと、その primary 以外の worktree で、合成した保存済みの履歴を使いました。Claude の認証はコピーしていません。app-server の推論の要求は止めてあり、1 度も試みていません。一時的な認証は、実行のあとで消しました。

macOS で公式の拡張を動かして確かめたこと:

- 別々の保存済みのスレッド 2 つ、行を繰り返しクリックしたときに内容が正確に出ること、会話のエディタのタブが開かないこと。
- 休止・再開と Worktabs の再起動のあとの内容、保存された Codex のプロバイダーの選択、Worktabs で隠した行が隠れたままであること。
- issue、PR のレビュー、日本語の自由な文のタスクが、ターンを送らずに、編集できる下書きになること。タスクの場合ごとに、その前の確認の下書きを消しました。
- primary 以外の worktree での最初の案内の自動処理と、その worktree での編集できるタスクの下書き。
- 入っている Claude Code と Codex のパネルの切り替えで、Codex の下書きが残ること。
- 公式の Codex のメニューからのアーカイブ、それで出る `thread/archive` の要求、その Worktabs の行が消えること。
- 存在しないスレッドで、復元の警告と、代わりに履歴から開く案内が出て、保存された Worktabs の行は残ること。

Windows でのオフラインの移動も、スレッドの履歴を最初に作ったときに確かめています。その結果は、回帰の確認の根拠としては役立ちますが、今のビルドでの、サインインした公式の拡張の受け入れの結果ではありません。

macOS でのオフラインの実行では、次のことを確かめました。新しいエディタのタブを開かない、2 つのスレッドへの経路。Worktabs の再起動のあとのメタデータ。補助拡張が登録する前のクリック。休止・再開。Worktabs のアーカイブの保存。Codex のアーカイブのイベントを模したあとの、行の削除。issue、PR のレビュー、日本語の自由な文のタスクは、ターンを始めずに、編集できる下書きとして出ました。単体テストでは、不正な ID、拡張がないとき、拒否された移動・再開、一時的な履歴、更新の保護、プロバイダーの設定、取り消し、入力の復旧も確かめています。

移動では、未読を消す前に、マウントされて見えている入力欄に、求めたスレッドが出ていることを確かめるようになりました。Electron でのオフラインの実行では、受け付けた URI のスレッドがいつまでも描画されないときに、期限に達し、代わりに履歴から開く案内の警告を出し、保存された行を残すことも確かめます。公式の拡張での実行では、React の要素を 100 段までしかたどらずに見つけられない、もともとの問題が再現しました。祖先の数は、導入の見出しが 134、新しい入力欄が 236、復元したスレッドの権限の操作部品が 257 でした。上限を 512 に上げると、マウントされた context を読めるようになりました。10,000 ノードの上限と、壊れたツリーへの保護は、そのまま保っています。新しい webview は、以前の 5 秒の移動の期限も超えたので、上限のある期限を 15 秒にしました。深い current・alternate のツリーと、起動の遅れの回帰テストは通ります。

公式の Codex 拡張 26.1007.21434、付属の CLI 0.162.0-alpha.17.2、空の `CODEX_HOME` で、ほかと切り離して動かすと、はじめは webview が空のままでした。拡張のログには、SQLite の state runtime の初期化の致命的な失敗が出ています。一時的なパスを短くしても、引き継いだ Codex のセッションの環境変数を消しても、直りませんでした。続く実行では、Worktabs を起動する前に、サインインしていない app-server を初期化しておくと、公式の拡張のサインインのパネルが出ました。ChatGPT でのサインイン、API キー、デバイスコードが選べ、利用枠は取得できないままでした。これらのサインインしていない実行では、スレッドの内容は確かめていません。内容は、そのあとの、許可を得てサインインした上の実行で確かめました。新しいホームでの起動の失敗は、まだ原因を調べる必要があります。事前に初期化して出たことは、その原因を示すものではありません。サインインしていない実行では、認証情報をコピーしていません。記録したどの実行でも、モデルへのターンは送っていません。

日本語の Electron の設定画面では、28 個の文字とアクセシビリティのラベル、対象環境と版の操作、実際のインポート・復元の検証のエラーを確かめました。OS のファイル選択ダイアログと、更新・インポート・復元の一連の処理の全体は、まだです。

## 公式の拡張での受け入れ

残っている実際のターンの確認と、延期したプラットフォームの確認には、このチェックリストを使います。上の移動、下書き、アーカイブの項目には macOS での根拠があります。ただし、項目が 1 つ合格しても、サインインしたマス全体が済んだことにはなりません。マスを済ませるときは、チェックリストを全部やり直します。「Claude だけ」のマスは、回帰の確認として行います。Codex に特有の手順は、「Codex だけ」と「両方のエージェント」のマスで行います。

- [ ] primary の worktree と、primary 以外の worktree を開きます。プロバイダーの選択、primary の最初の案内、primary 以外の worktree の最初の案内、エージェントの切り替えを確かめます。両方のエージェントを使うときは、行とバッジがプロバイダーごとに分かれていることを確かめます。
- [ ] 1 つのタブで、Codex のスレッドを 2 つ開きます。各行をクリックしたときの、タイトル、最新のプロンプト、cwd、経過の状態、スレッドごとに違う内容を確かめます。会話のエディタのタブは開かないはずです。
- [ ] ターンを実行し、承認かユーザーの入力を求めさせ、完了、失敗、中断させます。数、作業中・承認待ちの状態、未読の結果、停止の警告、次の承認待ちへの移動、通知のクリックを確かめます。クリックでは、求めたスレッドそのものが出なければなりません。
- [ ] issue、PR のレビュー、自由な文から worktree を作ります。編集できる最初の下書きと、Claude の動きが変わっていないことを確かめます。ユーザーが送るまで、何も送られてはいけません。すでにある下書きは、そのまま残します。入力できないときの警告と、「タスクをコピー」での復旧を確かめます。
- [ ] code-server を再起動し、タブを休止・再開し、Worktabs を再起動します。選んでいたタブとプロバイダー、戻った作業していない行、スレッドの内容、起動直後のクリック、承認の設定を確かめます。止めたプロセスは、終了していなければなりません。
- [ ] Worktabs で行を隠して、再起動します。行は隠れたままで、Codex のログはアーカイブしません。新しいプロンプトを送ると、また出ます。動いている Codex 拡張でアーカイブか削除をして、保存された行が消えることを確かめます。
- [ ] 見つからない・削除したスレッド、一時的なスレッド、使える拡張のないタブを開きます。対処のしかたがわかる警告と、代わりにサイドバーか履歴から開く案内が出ることを確かめます。
- [ ] サインインしたアカウント、API キーだけのモード、サインアウト、アカウントの切り替え、期限切れのデータ、読み取りの失敗で、利用枠を確かめます。わからない利用枠を、0 と表示してはいけません。
- [ ] 拡張の更新の適用、再インポート、復元をします。作業していない・作業中のときの保護、未保存の編集、プロセスの終了、戻すときのエラー、付属の実行ファイルの選び直しを確かめます。

## 失敗の表

| 状況 | 期待する結果 | 今の根拠 | 実機での状況 |
|---|---|---|---|
| サインインしていない、または認証の期限切れ | パネルがサインインを勧める。ブランチ名を考えるときは、どこでサインインするかを説明する。利用枠は取得できないまま | CLI のエラーの分類と、利用枠のテスト | macOS で、app-server を事前に初期化したあと、公式の拡張のサインインのパネルと、利用枠を取得できないことを確認。サインインしたときとの比較と、ほかのプラットフォームはまだ |
| PATH に別の CLI がない | インポートした拡張に付属する実行ファイルを使う | 手元と WSL での、実行ファイルを探すテスト | サインインしての、端から端までの実行はまだ |
| 付属の実行ファイルがないか、対応していない | 準備のメッセージが、コンピューターか WSL のディストリと、合う拡張のインポートのしかたを示す | バイナリとプラットフォームの検証のテスト | まだ |
| 拡張のインストールかインポートに失敗する | 設定にエラーが残る。途中までのインポートは、できれば前の版に戻す | 検証、インポートのトランザクション、日本語の IPC のテスト | 一連の処理の全体はまだ |
| スレッドか URI の経路を復元できない | 警告が失敗を説明し、代わりにサイドバーか履歴から開く案内を出す | 補助拡張、プロトコル、保存のテスト | macOS で、公式の拡張の移動、再起動、休止、アーカイブ、見つからないスレッドでの代わりの案内を確認。ほかのプラットフォームは延期 |
| 入力欄が使えない、変わった、すでに下書きがある | 既存の入力には触れない。元のタスクをコピーできる | 入力の保護と復旧のテスト。Electron でのオフラインの入力の実行 | macOS で、公式の拡張の issue、PR、自由な文、primary 以外の worktree の下書きを確認。入力を守る場面の失敗は、引き続き自動テストで確かめている |

実際の失敗のテストごとに、出たメッセージと復旧の結果を、秘密の情報を除いて記録します。失敗した確認は、直したあとでもう一度確かめるまで、失敗のままです。延期した確認は、あとでメンテナーが確かめます。実装とドキュメントの issue を閉じるときも、この表ではまだのままにしておきます。表全体を合格とは書きません。

## リリースノートの範囲

Codex との連携には、プロバイダーの設定、状態のバッジ、スレッドへの移動のメタデータ、使用量、承認の設定、編集できる最初のタスクの下書きが含まれます。Claude と Codex は、一緒に有効にできます。Codex には、利用者が用意した対応する拡張と、動かす環境ごとのサインインが要ります。移動、入力欄、最初の案内、権限の連携は、入っている拡張の版によります。macOS の公式の拡張での移動、復元、タスクの下書き、primary 以外の worktree の最初の案内、アーカイブの扱い、パネルの切り替えは、モデルのターンなしで確かめています。実際のターンでの動き、Claude の認証の回帰の確認の全体、Windows、WSL はまだです。Windows と WSL は、メンテナーの判断で延期しています。まだ、これらの環境すべてに完全に対応しているとは書かないでください。
