# 使い方

[English](../usage.md) | **日本語**

左のサイドバーで worktree を選ぶと、その worktree の VS Code（code-server）がタブとして右に開きます。ウィンドウの地図と、それぞれの部分でできることは [features.md](features.md)、worktree の追加と削除は [worktrees.md](worktrees.md)、WSL のリポジトリは [wsl.md](wsl.md) にあります。

## サイドバー

Claude Code と Codex の会話は、同じ状態のバッジと、作業中・承認待ちの数を使います。Codex の承認・権限・入力の求めも、承認待ちに数えます。Codex の会話の行、通知、次の承認待ちに移るバッジをクリックすると、Codex のチャット欄をそのスレッドに切り替えます。エディタのタブは開きません。バックグラウンドで完了したときとエラーになったときは、通知を出し、未読の結果を残します。タブを閉じる・休止する・再起動するときは、どちらかのエージェントが作業中か承認待ちなら、警告します。

サイドバーは、リポジトリ → worktree → 会話のツリーです。

ほかのウィンドウが前にあるときも、行を 1 回クリックすれば、Worktabs のウィンドウが前に出て、その行の動き（タブの切り替えなど）もします。macOS も同じで、タブの VS Code も 1 回のクリックで効きます（[architecture.md](architecture.md#サイドバーの作り直し)）。

### 節

ツリーは 3 つの節に分かれます。

- **開いているリポジトリ**: 開いているタブがあるリポジトリ（名前順）と、「その他のフォルダ」。タブがなければ、節ごと出ません。
- **ほかのリポジトリ**: 残りのリポジトリ。最近までタブを開いていた順に並び、開いたことがないものはその後に名前順です。リポジトリもタブも 1 つもないとき（ghq がないときなど）は、追加のしかたを出します。
- **クローンしていないリポジトリ**: 自分と、自分が入っている org の GitHub のリポジトリのうち、まだクローンしていないもの（下記「[クローンしていないリポジトリ](#クローンしていないリポジトリ)」）。gh がない・サインインしていないときは、節ごと出ません。

節の見出しは、次のように動きます。

- 見出しをクリックすると、節を畳めます。畳んだ「開いているリポジトリ」の見出しには、開いているタブのうち最も緊急な状態のバッジが出ます。サイドバーから worktree を開くと、「開いているリポジトリ」は開きます。絞り込みの入力中は、畳んでいても当たったものを出します。
- 「クローンしていないリポジトリ」は、初めは畳んであります。数が多いと、ふだん使うリポジトリの一覧が長くなるためです。見出しに、リポジトリの数が出ます。
- スクロールしても、節の見出しはその節の上端に残ります。
- 最後にタブを開いていた時刻は、リポジトリごとにデータフォルダの `tabs.json` に記録します。

### リポジトリ

ghq（WSL の中を含む）・手動で追加したリポジトリと、開いているタブのリポジトリが並びます。

- 一覧は、データフォルダの `repos.json` に残します。起動したら、まず前回の一覧を出し、裏で読み直して、読み終わったら差し替えます。読み直している間は、上端の回る矢印が回ります。展開しているリポジトリの worktree の行も、前回の分をまず出します。
  - `repos.json` がない初回だけは、一覧を読み終わってから出します。
  - 一覧を読み直すのは、起動したとき、回る矢印を押したとき、「リポジトリを追加…」のあとです。足したリポジトリは、読み直しを待たずにすぐ出ます。ウィンドウが前に来たときには読み直しません。止まっている WSL を、そのたびに起動してしまうためです。
  - 読み直せなかった取得元（WSL が時間内に応えないなど）のリポジトリは、前回の分を残します。理由は、データフォルダの `logs\repos.log` に 1 行で残します。

- タブを開くと、そのリポジトリは「開いているリポジトリ」に移り、自動で展開されます。
- 畳んでいるときは、開いているタブのうち最も緊急な状態のバッジが、リポジトリの行に出ます。
- 名前の前に、リモート（origin、なければ最初のリモート）がどこにあるかのアイコンが出ます。

  | アイコン | リモート |
  | --- | --- |
  | GitHub・GitLab・Bitbucket のロゴ | それぞれのサービス。GitHub は Enterprise を、GitLab と Bitbucket は `gitlab.`・`bitbucket.` で始まる社内のサーバーを含みます |
  | 本 | そのほかのリモート（Gitea・社内の Git サーバー・パスなど）と、リモートのないリポジトリ。リモートを読む前（初めての起動）も、これが出ます |
  | フォルダ | git でないフォルダと、「その他のフォルダ」 |

  - マウスを乗せると、`GitLab`・`リモートなし` のように出ます。
  - リモートは、メインプロセスが一覧のすべてのリポジトリについて読み、`repos.json` に残します。読むのは一覧に初めて載ったときと、回る矢印を押したときです（どのホストをどのサービスとみなすかは [architecture.md](architecture.md#github-のボタン)）。
- リモートが GitHub のリポジトリは、名前の横に GitHub での公開範囲のアイコンが出ます。private は鍵、internal（Enterprise のメンバーに公開）は建物です。public には出ません。マウスを乗せると「GitHub: 非公開（private）」のように出ます（public も）。
  - 公開範囲は、一覧を読み直すたびに gh で GitHub に聞き、`repos.json` に残します。次の起動では、聞き終わる前から前回の分が出ます。
  - gh がない・サインインしていないとき、見られないリポジトリ（消えた、権限がない）には、何も出ません。
- 自分が作った PR のうち、Approve 済みでまだマージしていないものがあるリポジトリは、行の左のアイコン（GitHub のロゴ）の右上に赤い点が出ます。畳んでいても、その PR のブランチの worktree が手元になくても出ます。行の幅は変わりません。
  - どの PR かは、行の名前にマウスを乗せると出ます（「Approve 済みでマージしていない PR:」と、番号・題名）。アイコンに乗せると出る GitHub のボタンの下にも並び、押すとその PR を開きます（下記「[GitHub のページ](#github-のページ)」）。
  - Approve 済みかは、GitHub の判定に従います（レビューを必須にしたブランチ）。レビューを必須にしていないリポジトリでは、書き込みのできる人の最後のレビューに Approve があり、変更の依頼がないときです。ドラフトの PR と、アーカイブしたリポジトリの PR には出ません。
  - 人の PR（レビュー用に作った worktree など）には出ません。マージするのは作った人だからです。
  - 読み直すのは、一覧を読み直したあと、5 分おき、Worktabs のウィンドウが前に来たとき（前に読んでから 1 分たっていれば）、Claude が push やマージ（`git push`・`gh pr merge` など）をしたあとです。Approve は GitHub で人がするので、アプリには知らされないためです。展開しているリポジトリで、worktree の行の PR がマージ済みやクローズになったものは、すぐに消えます。
  - WSL のリポジトリは、一覧を読み直したあと以外は、そのディストリが動いているときだけ読み直します。止まっている WSL を起動しないためです。
  - GitHub のリポジトリだけです。GitLab・Bitbucket の MR・PR は読みません。gh がない・サインインしていないときは出ません。
- クリックすると worktree の一覧（`git worktree list`）が出ます。一覧は、展開したとき・Worktabs のウィンドウが前に来たとき・Claude の作業が終わったときに読み直します。アプリの外で作った worktree も、これで出ます。
- worktree の行は、リポジトリの名前の位置まで字下げして出ます。会話の行は、worktree の名前の位置まで字下げします。
  - 開いているか畳んでいるかの印（▸）はありません。すぐ下に字下げした行があれば、開いています。印の列の幅を、名前に使うためです。
- git リポジトリの外で開いたフォルダは、「その他のフォルダ」にまとまります。
- ghq の一覧にある git でないフォルダ（SVN のチェックアウトなど）は、worktree を持ちません。展開すると、そのフォルダ 1 行だけが出て、クリックでそのままタブとして開きます。「＋」と GitHub のボタンは出ません（タブを開いていれば、下の「すべてのタブを閉じる」のボタンは出ます）。そのフォルダの中で開いたタブは、「その他のフォルダ」ではなく、その行の下に出ます。
- マウスを乗せると出る「＋」か、右クリックの「worktree を追加…」で、worktree を追加するダイアログが出ます。GitHub の issue ややることから、ブランチ名を Claude に考えさせることもできます（[worktrees.md](worktrees.md)）。
- 開いているタブがある行（「その他のフォルダ」と git でないフォルダの行を含む）には、マウスを乗せると「すべてのタブを閉じる」のボタン（VS Code の「すべて閉じる」と同じアイコン）が出ます。押すと、その行のタブをまとめて閉じます。行を畳んでいるときや、絞り込みで隠れているタブも閉じます。右クリックの「すべてのタブを閉じる」も同じです。
  - Claude が作業中・承認待ちのタブと、保存していないファイルがあるタブがあれば、それらを並べて 1 回だけ確認します（終了の確認と同じ）。どれもなければ、聞かずに閉じます。
  - 前に出ているタブも閉じるときは、その行の外のタブに移ります。タブの並び（Ctrl+Alt+PageDown の順）で後ろにあるもの、なければ前にあるものです。なければタブなしになります。閉じるタブを途中で前に出さないので、休止中のタブを起動してしまうこともありません。
  - 閉じたタブは、× で閉じたときと同じく、開き直すと閉じる前の画面に戻ります。
  - タブがなくなると、行は「ほかのリポジトリ」に移り、その場所に下の行が上がってきます。その行のタブまで続けて閉じないように、閉じている間と閉じたあと 0.6 秒は、ツリーのクリックを受け付けません（ダブルクリックの 2 回目も）。
  - ボタンは「＋」の左に、少し離して出ます。展開した行の右端にある「＋」の場所は変わりません。

### クローンしていないリポジトリ

gh がサインインしている GitHub のアカウント（GitHub Enterprise を含む）の、自分が owner のリポジトリ（自分のフォークを含む）と、自分が入っている org のリポジトリのうち、クローンしていないものが並びます。新しい PC で作業を始めるときや、しばらく触っていないリポジトリに戻るときに、ターミナルで `ghq get` しなくても、ここからクローンできます。

- 出さないもの: クローン済みのもの（Windows と WSL のどちらにあっても）、アーカイブしたもの、collaborator として入っているだけのほかの人のリポジトリ。
  - クローン済みかは、一覧のリポジトリのリモートの URL と、大文字小文字を区別せずに比べます。名前を変えた・owner を移したリポジトリも、GitHub が答えた今の URL で比べるので、ここには出ません。
  - リモートをまだ読んでいないリポジトリ（アプリの外でクローンしたばかりのものなど）も、ghq の並び（`.../<ホスト>/<owner>/<名前>`）のフォルダなら、クローン済みとみなします。
- 一覧を読み直すたび（起動したとき・回る矢印・「リポジトリを追加…」のあと）に、リモートを読み終えてから gh で GitHub に聞きます。初めての起動でも、クローン済みのものが一瞬でも出ることはありません。
  - 結果はデータフォルダの `repos.json` に残し、次の起動では聞き終わる前から前回の分が出ます。聞けなかったホストは、前回の分を残します。
- owner の行の下に、その owner のリポジトリの行が、owner の名前の位置まで字下げして並びます。
  - owner の行は、自分のアカウントが先で、org が名前順で続きます。人か組織のアイコン・名前・クローンしていないリポジトリの数が出ます。github.com 以外のホストの owner には、名前の横にホストが出ます。
  - 自分のアカウントは開いていて、org は畳んであります（大きな org は、リポジトリが数百あるため）。開いているかどうかは覚えておきます。
  - owner の行の右クリックで、「GitHub で開く」と「この owner を出さない」が出ます。出さない owner は、設定の `hiddenGithubOwners` に入ります（戻すときは設定ファイルから消します。[config.md](config.md)）。
- リポジトリの行には、GitHub のロゴ・名前・公開範囲のアイコン（private は鍵、internal は建物）が出ます。最後に push した順に並びます。
  - マウスを乗せると、URL・説明・フォークかどうか・最後の push の日が出ます。
  - マウスを乗せると出るボタン（下向きの矢印）か、右クリックの「クローン」でクローンします。右クリックには「GitHub で開く」と「URL をコピー」もあります。
- クローンの仕方:
  - ghq があれば（`ghq root` が動けば）、`ghq get` でクローンします。クローン先は ghq が決めます。
  - ghq がなければ、クローン先を入れるダイアログが出て、`git clone` でクローンします（下記「[クローン先のダイアログ](#クローン先のダイアログ)」）。
  - https か SSH かは、gh の設定（`gh config get git_protocol`。`gh auth login` で選んだもの）に合わせます。`gh repo clone` と同じです。SSH なら `ghq get -p`・`git@<ホスト>:<owner>/<名前>.git` です。
  - Windows では、WSL のディストリにもクローンできます。ボタンを押すと、クローン先を「Windows」「WSL: <ディストリ名>」から選ぶメニューが出ます（[wsl.md](wsl.md#クローンする)）。候補が Windows だけなら、メニューは出ずにすぐクローンします。macOS も、すぐクローンします。
- クローンしている間は、行に「クローン中…」と出て、ボタンは出ません。大きなリポジトリもあるので、10 分までは待ちます。
- 終わると、そのリポジトリは「ほかのリポジトリ」に移り、展開して primary の行が出ます。
  - ghq でクローンして、設定の `repoSources` が ghq を読んでいないとき（WSL では、そのディストリを読んでいないとき）と、`git clone` でクローンしたときは、そのフォルダを設定の `repos` に足します（「リポジトリを追加…」と同じ）。
- 失敗すると、ghq・git の出力をダイアログで出します。
  - https で認証に失敗したときは、git に GitHub の認証情報を渡す方法（Git Credential Manager か `gh auth setup-git`）も出します。gh のサインインと git の認証情報は別です。
  - SSH で鍵が通らない・ホストの鍵を受け入れていないときは、ターミナルで `ssh -T git@github.com` を一度実行するよう出します。アプリにはホストの鍵を受け入れるかを聞く場所がないためです。

#### クローン先のダイアログ

ghq がないときに、どこにクローンするかを聞きます。

- 欄には、クローンする先のフォルダの完全なパスが入ります。そこにもうフォルダがあるときは、クローンできません（欄の下に赤で出ます）。
- 下に、一覧のクローン済みのリポジトリがある場所が、リポジトリの多い順に出ます。押すと、その場所にクローンするパスが欄に入ります。
  - ghq の並び（`<root>/<ホスト>/<owner>/<名前>`）のリポジトリがある場所は、`<root>` にも同じ並びでクローンします。それ以外のリポジトリがある場所は、`<親のフォルダ>/<名前>` にクローンします。
  - WSL にクローンするときは、そのディストリのリポジトリの場所が出ます。
- 「参照…」で、フォルダを選んでも構いません。選んだフォルダの下に `<名前>` で入ります。選んだフォルダにホストのフォルダ（`github.com` など）があれば、ghq と同じ並びにします。
- 最後にクローンした場所は、設定の `cloneRoot` に覚え、次はそこから始めます。
- Enter でクローン、Esc でキャンセルです。クローンが始まると、ダイアログは閉じます。

### worktree

フォルダ名と、横にブランチ名が出ます。

- メインの worktree（リポジトリのフォルダそのもの）は `primary` と出ます。フォルダ名はリポジトリ名と同じで、`main` だとブランチと紛れるためです。
- リポジトリの隣にある `<リポジトリ名>-<名前>` のフォルダは、`<名前>` だけが出ます（`worktabs-feat-x` なら `feat-x`）。
- フォルダ名がブランチ名と同じとき（`/` を `-` にしたものを含む）は、ブランチ名を出しません。サイドバーで追加した worktree は、ブランチ名から名前を付けるためです（`feat/x` なら `feat-x`）。ブランチ名は、行にマウスを乗せると出ます。
- クリックすると、タブとして開きます（code-server の起動は約 1 秒）。開いているものは、そのタブに切り替えます。
- 初めての起動でのダウンロード中や、拡張のインストール中は、タブに「code-server と拡張機能を準備しています…」と出て、準備が終わるのを待ちます。待っている間も、タブを切り替えたり閉じたりできます。準備中に新しいタブを開いても、保存してあるタブはそのまま残ります。準備に失敗すると、タブにエラーが出ます。原因を直して、Worktabs を起動し直してください。
- 開いている worktree にはバッジが付きます。× か中クリックで閉じ、右クリックでタブのメニュー（下記「タブ」）が出ます。開いていない worktree の右クリックでは、開く・エクスプローラーで開く（macOS では Finder で開く）・このブランチの PR・パスをコピー・削除が出ます。
- 開いていない worktree の行にマウスを乗せると、右端（開いているときの × の場所）にゴミ箱のボタンが出ます。押すと、右クリックの「worktree を削除…」と同じ確認が出ます（[worktrees.md](worktrees.md#削除)）。primary・ロックされた worktree・開いている worktree には出ません。PR がマージ済みで、ブランチの先頭が PR の最後のコミットと同じ worktree には、マウスを乗せなくても出ます。
- ブランチ名は、Worktabs のウィンドウが前に来たときと、Claude の作業が終わったときに読み直します。
- GitHub の issue から作った worktree は、ブランチ名の横に `#20` のように issue の番号が出ます。マウスを乗せると題名が出て、押すと GitHub で issue を開きます（[worktrees.md](worktrees.md#作ったあと)）。
- ブランチに PR があると、PR のアイコンと番号が出ます。PR がない行（既定のブランチの行を含む）には、HEAD のコミットの CI の結果が出ます（下記「[PR と CI](#pr-と-ci)」）。

### 会話

開いている worktree で Claude Code か Codex の会話があると、その下に会話ごとの行が出ます（会話が 1 つでも出ます）。Claude の星形のマークは Claude Code の会話、Codex 拡張も使っている OpenAI の結び目のマークは Codex の会話です。このマークは、タブの既定のエージェントが違っても、その会話のエージェントに従います。エージェントが作業中や承認待ちの間も、別に出る状態のバッジの横に残ります。Claude のマークは Claude のオレンジ、Codex のマークは黒か白で、どちらのテーマでも、それぞれの拡張と同じ色です。どちらもリポジトリの GitHub のマークと同じ大きさで、サイドバーが狭くても小さくなりません。

行には、状態のバッジ、エージェントのアイコン、会話の題名の順に出ます。題名が付く前は、最後に送ったプロンプトが出ます。マウスを乗せると、エージェントの名前と状態が出て、題名のある会話では最後に送ったプロンプトも出ます。行のアクセシビリティのラベル（スクリーンリーダーが読む名前）にも、同じことが入っています。絞り込みは、題名とプロンプトの両方から探します。

Codex の行は、スレッドの ID、最後のターンの ID、題名、最後に送ったプロンプト、作業フォルダを覚えています。アプリを起動し直すと、復元した Worktabs のタブの行は、待機中で戻ります。タブを休止したり、その app-server を閉じたりしても、使った Codex のスレッドは、また開けるように残ります。Worktabs は、Codex の履歴のスレッドをすべて取り込むわけではありません。そのタブで使うか再開したスレッドに、行ができます。一時的な（ephemeral）スレッドは、復元できる履歴として保存しません。会話の中身は、Codex 自身の保存場所に残ります。

Codex が内部で題名や説明を作るためのスレッドは、会話として出ず、バッジ・数・未読の結果・通知・タブを止めるときの警告にも影響しません。ユーザーが作った一時的な会話は、開いている間は出ます。

Codex が仕事を任せたエージェント（サブエージェント）の行には、「サブ」の札（ツールチップでは「サブエージェント」）が付き、分かればニックネーム、役割、エージェントのパスが出ます。それぞれ、自分を始めた会話の 1 段下に出ます。親の会話をアーカイブしたときや、親が絞り込みで隠れているときは、字下げせずに、ほかの会話と同じ段に出ます。クリックすると、そのサブエージェント自身のスレッドを開くので、何をしたかを見られます。サブエージェントの行にも作業中と承認待ちのバッジは出ますが、終わっても、緑の未読の結果や完了の通知を別には出しません。結果は、親の会話がまとめて伝えます。サブエージェントの完了の知らせが届かなかったときは、親が伝えてくるサブエージェントの状態から補います。サブエージェントを始めるツールや待つツールが終わっただけでは、サブエージェントが終わったとはみなしません。名前、役割、親の ID は、一度分かれば、アプリを起動し直しても残ります。前から保存してある行には、次に拡張がその情報を伝えてきたときに、これらの札が付きます。内部で使う guardian・レビュー・compaction のスレッドは出しません。

復元した行をクリックすると、タブの補助拡張がアプリに登録するのを待ってから、チャット欄を保存してあるスレッドに切り替えます。拡張か、そこへの経路が使えないときは、Worktabs が失敗した理由を出し、Codex のチャット欄を出そうとします。スレッドの再開を断られたときも、警告を出します。削除・アーカイブしたスレッドや、別の Codex のホームフォルダに移したスレッドは、復元できないことがあります。

Worktabs は、頼んだスレッドが、見えている Codex のチャット欄に出るまで、5 秒まで待ちます。URI を送っただけでは、前に出せたとはみなさず、未読の結果も消しません。チャット欄が空白のときや、対応していないチャット欄のときも、同じ警告を出し、代わりに履歴を出します。タブを切り替える、起動し直す、別のスレッドを選ぶと、前の確認はやめます。

- 行の右端に、今の状態になってからの時間が出ます。作業中と承認待ちは、その状態が続いている時間（「12 分」「1 時間」「2 日」）です。完了とエラーは、ターンが終わってからの時間（「5 分前」）です。
  - 1 分たつまでは出ません。待機中の会話には出ません。
  - 時間は 1 分ごとに進みます。行にマウスを乗せると、その状態になった時刻が出ます（「作業中（14:03 から）」）。
  - 状態が変わるたびに、0 から数え直します。承認して作業に戻ると、作業中の時間は承認したときからになります。
  - 時刻はアプリの中にだけ持ちます。アプリを起動し直すと、会話は待機中から始まるので、次に作業を始めるまで時間は出ません。
- 会話の行をクリックすると、そのタブに切り替えて、その会話を前に出します。エディタのタブにある会話は、そのタブを前に出します。右のパネル（チャット欄）の会話は、右のパネルをその会話に切り替えます。
- 右のパネルで新しい会話を始めたり、履歴から別の会話を選んだりしても、前の会話は裏で動き続けます（claude のプロセスが残ります）。このため、前の会話の行も残ります。行をクリックすると、右のパネルがその会話に戻ります。
- 待機中・完了・エラーの会話の行には、マウスを載せるとアーカイブのボタンが出ます。押すと、その行を一覧から外します。
  - 会話の claude は止めません。背後で作業を続けていれば、そのまま続きます。Claude Code 拡張の会話一覧のアーカイブと同じです。
  - 作業中と承認待ちの会話は、アーカイブできません。アーカイブした会話も、また作業中か承認待ちになると一覧に戻ります（右のパネルの履歴から開いて、プロンプトを送ったときなど）。取り消すボタンはないので、戻すときはこの方法を使います。
  - 完了して未読の会話は、アーカイブすると既読になります。
  - アーカイブは Worktabs の中だけの印です。Codex では、この印はアプリを起動し直しても残ります。Codex の `thread/archive` は呼ばず、保存されたスレッドのログも動かしません。動いている Codex 拡張が、スレッドを本当にアーカイブしたか削除したと知らせてきたときは、Worktabs も保存している行を消します。読み込んだスレッドを閉じただけでは、保存している行は消えません。
- worktree の行のバッジは、その worktree の会話のうち最も緊急な状態です。アーカイブした会話は数えません。
- Claude が別の worktree に移って作業していると、行に「→ 移った先」が出ます。会話のパネルは元のタブの VS Code に残るので、クリックすると元のタブに移ります。

### 絞り込み

上の欄に入力すると、リポジトリ名・worktree 名・ブランチ名・issue の番号（`#20`）と題名・会話の題名で絞り込めます。Esc で解除します。

- 「クローンしていないリポジトリ」では、リポジトリの名前・説明と、owner の名前で絞り込みます。リポジトリが当たった owner は開きます。owner の名前が当たったときは、その owner のリポジトリをすべて出します（owner は開いたり畳んだりしたままです）。

### 上端

- 「Worktabs」の右に、承認待ちの会話の数（橙）と、作業中の会話の数（青）のバッジが出ます。0 のものは出ません。
  - 数えるのは、タブではなく会話です。1 つのタブで 2 つの会話が承認待ちなら 2 です。ウィンドウのタイトルの数も同じです。
  - バッジを押すと、その状態の会話に移ります。押すたびに次の会話に移り、最後まで行くと最初に戻ります（タブを開いた順、同じタブの中では会話を始めた順）。
- 右のボタン:
  - 回る矢印（リポジトリ一覧を更新）: ghq（WSL の中を含む）と設定のリポジトリを読み直し、展開しているリポジトリの worktree と、リモート（行のアイコンと公開範囲のアイコンのため、すべてのリポジトリの分。SSH の別名と gh のサインインも聞き直します）も読み直します。読み終わるまで、アイコンが回ります。クローンしていないリポジトリも、そのあとに GitHub に聞き直します（アイコンは回りません）。
  - 「＋」: リポジトリを追加…（選んだフォルダの git リポジトリを設定に加えます）、フォルダを開く…（git 管理外のフォルダも開けます）。
  - 歯車: 設定のダイアログを開きます。
  - 「…」: code-server と拡張の更新を確認（新しい版があれば、サイドバーに出します）、設定ファイルを開く（設定ファイルを既定のエディタで開きます）。

### 幅

サイドバーの右端をドラッグすると、幅を変えられます。マウスを乗せて少しすると、右端に線が出ます。

- ドラッグしている間、右のタブもその幅に合わせて動きます。
- 幅は 180〜600 ピクセルです。ウィンドウが狭いときは、右のタブに 320 ピクセルを残すところまでにします。ウィンドウを広げると、ドラッグで決めた幅に戻ります。
- 変えた幅は、データフォルダの `window.json` に残し、次の起動で戻します。
- 右端をダブルクリックすると、既定の幅（設定の `sidebarWidth`。既定は 260 ピクセル）に戻ります（[config.md](config.md)）。

### 色

サイドバーの色は、前に出ているタブの VS Code のテーマに合わせます（背景・文字・区切り・選んでいる行・入力欄・数のバッジ）。タブを切り替えたときと、VS Code でテーマを変えたときに変わります。タブの準備中の画面も同じ色です。

- 状態の点、「承認待ち」の文字、WSL の印、サブスクリプションの使用量のバーの色は、テーマに関係なくアプリで決めています（明るいテーマ用と暗いテーマ用の 2 組）。暗いテーマでは、作業中と承認待ちの点が少し光ります（OS で「アニメーション効果」を切っていると光りません）。
- 最後に合わせたテーマは、データフォルダの `theme.json` に残し、次の起動ではまずその色で出ます。一度もテーマを読んでいないときは、OS のライト／ダークに合わせます。

## 確認や警告のダイアログ

閉じる・終了の確認や worktree の削除などのダイアログも、サイドバーと同じテーマの色で、VS Code のダイアログと同じ形に出ます。ウィンドウ全体を暗くして、中央に出します。

- Enter でフォーカスのあるボタン（ボタン以外にフォーカスがあるときは既定のボタン）、Esc でキャンセルです。Tab はダイアログの中だけを回り、左右の矢印キーでボタンを移ります。
- 閉じると、前にフォーカスがあったタブかサイドバーに戻ります。
- 詳しい説明の文字は、選んでコピーできます。何も選ばずに Ctrl+C を押すと、見出しと説明をまとめてコピーします。
- 2 つ出るときは、順に出します。ダイアログを出したままウィンドウを閉じると、ダイアログはキャンセルになり、終了の確認に進みます。

## バッジと通知

| 表示 | 状態 |
|---|---|
| 灰色の点 | 待機中 |
| 青の回転 | 作業中 |
| 橙の点滅＋「承認待ち」 | 権限の確認や質問に答える必要がある |
| 緑の点 | 完了（その会話の結果をまだ見ていない） |
| 赤の点 | エラー、または code-server が停止 |
| 白抜きの丸 | 休止中 |

タブを開いたときやウィンドウに戻ったときに既読になるのは、見えているチャット欄かエディタに出ている会話だけです。ほかの会話は、同じタブのもう一方のエージェントの結果も含めて、未読のままです。チャット欄のエージェントや会話を切り替えると、数秒でその会話が既読になります。チャット欄が隠れている、まだ読み込み中、どの会話か分からないときは、未読のままです。会話の行をクリックしたときは、その会話を開けたときに、その行だけが既読になります。

バックグラウンドのタブで Claude Code か Codex の会話が「承認待ち」「完了」「エラー」になると、OS の通知が出ます。Worktabs のウィンドウが非アクティブなときも出ます。アクティブでフォーカスのあるタブで、ほかのチャットの裏にある結果は、通知を出さずに未読になります。

- 通知は会話ごとに出るので、同じタブのほかの会話が作業中でも届きます。
- 通知をクリックすると、そのタブに移ってその会話を前に出します。トーストが消えたあとに、通知センターからクリックしても同じです。
- アプリを起動し直す前の通知をクリックすると、そのタブに移ります。会話は前に出ません。アプリを終了していれば、アプリが起動します。
- 承認待ちでウィンドウが非アクティブなら、タスクバーも点滅します。

## タブ

### Codex の承認

新しい Codex の会話では、拡張が許せば、Worktabs は「Approve for me」（承認の求めを Codex 自身に審査させるモード）を選びます。手で承認するときは、「設定 > 一般 > Codex の新しい会話の承認 > 承認を求める」を選びます。この設定は Worktabs のタブで共有し、起動し直しても残ります。Claude の権限の設定とは別です。

Codex の権限の切り替えには、実際に効いているモードが出ます。自動の審査を使えないときは、拡張はふつう「Ask for approval」のままです。保存してある会話を再開すると、その会話のモードのままです。開いているチャット欄で自分でモードを変えると、そのチャット欄ではそちらが優先です。Worktabs の設定を変えると、次の新しい会話から効きます。自動の審査でもサンドボックスはそのままで、求めを断ることもあります。

### Claude のパネル

Claude のパネルは、アクティビティバーの Claude アイコン（Session Manager）から「New session」で開きます。会話の履歴は `~/.claude` にあるので、ほかの VS Code や CLI の会話も一覧に出ます。

初めて開くタブ（新しい worktree など）では、VS Code の右のサイドバーに Claude Code のチャット欄を出します。フォーカスはエディタに残ります。VS Code はそこにまず組み込みのチャットを出しますが、AI の機能を切っているので中身がありません。右のサイドバーを閉じたり、ほかのビューに替えたりしたタブは、そのままにします（[architecture.md](architecture.md#補助拡張)）。

チャット欄の幅は、同じリポジトリの primary のチャット欄と同じにします。primary を初めて開いたときと、primary を開いたことがないリポジトリの worktree、git でないフォルダでは、エディタ欄とチャット欄がおよそ 2:1 になる幅にします。primary を閉じていても（アプリを起動し直したあとも）、アプリが覚えている primary の幅を使います。2 回目からは、VS Code が覚えている幅（自分で変えた幅）のままです（[architecture.md](architecture.md#右のチャット欄の幅)）。

### VS Code の設定

同じリポジトリの worktree のタブは、VS Code の設定を共有します。

- 設定（テーマ・フォントなど）、キーボードショートカット、スニペット、ユーザーのタスクと MCP の設定が対象です。
- 1 つのタブで設定を変えると、同じリポジトリのほかの実行中のタブにも、すぐに反映します。休止しているタブには、次に起動したときに反映します。新しい worktree のタブも、同じ設定で始まります。
- キーボードショートカット・スニペット・タスク・MCP の設定は、ほかのタブには、次にそのタブを起動したとき（再起動・休止からの復帰）に反映します。
- リポジトリが違うタブとは共有しません。git でないフォルダのタブは、タブごとの設定です。
- 拡張の有効・無効、パネルの配置、コマンドの履歴は、タブごとのままです（[limitations.md](limitations.md#vs-code-の設定)）。

仕組みは [architecture.md](architecture.md#vs-code-の設定の共有) にあります。

### キー操作

- Ctrl+Alt+PageUp / PageDown で前後のタブへ移る（タブを開いた順）
- それ以外のキー（Ctrl+W、Ctrl+Tab、Ctrl+P など）はすべて VS Code に届く

### 右クリックメニュー

開いている worktree の右クリックで出ます。

- 再起動
- 休止する
- 再読み込み
- エクスプローラーで開く（macOS では「Finder で開く」）
- このブランチの PR（リモートが GitHub で、既定のブランチ以外のとき）
- パスをコピー
- 開発者ツール
- 閉じる
- worktree を削除…（primary 以外）

リポジトリの行の右クリックでは、worktree を追加…（git のリポジトリだけ）・GitHub（リポジトリ・Issues・Pull requests・Actions。リモートが GitHub のとき）・エクスプローラーで開く・パスをコピー・すべてのタブを閉じる（開いているタブがあるとき）が出ます。「その他のフォルダ」の行では、すべてのタブを閉じるだけが出ます。

「エクスプローラーで開く」と、VS Code のエクスプローラーの右クリックにある「エクスプローラーで表示する」は、エクスプローラーのウィンドウが開いていれば、一番手前のウィンドウに新しいタブとして開きます（別の仮想デスクトップにあるウィンドウは使いません）。なければ新しいウィンドウで開きます。

macOS では、それぞれ「Finder で開く」「Finder で表示する」で、Finder で開きます。タブにはまとめません（[limitations.md](limitations.md#macos)）。

### 休止と復元

- 休止すると、そのタブの code-server と claude を止めてメモリを空けます。タブをクリックすると約 3 秒で戻り、開いていた Claude の会話タブも内容ごと復元されます。
- 設定の `idleSuspendMinutes` で、使っていないタブを自動で休止できます（[config.md](config.md)）。
- 前回開いていたタブは次回起動時に復元されます。起動するのはアクティブなタブだけで、ほかのタブは選んだときに起動します。
- 閉じたタブを開き直したときも、閉じる前の画面（開いていたファイル、エディタのタブの Claude の会話、サイドバーのビュー、パネルの大きさ）に戻ります。アプリを起動し直したあとも同じです。worktree を削除すると、戻せなくなります（[architecture.md](architecture.md#code-server)）。
- ウィンドウの大きさ・位置・最大化も、閉じたとき（と、動かしたり大きさを変えたりしたとき）のものを、次の起動で戻します（データフォルダの `window.json`）。サイドバーの幅も同じです（[上](#幅)）。
  - モニターを外したなどで、保存した位置ではどの画面にもほとんど映らないときは、大きさだけを戻して真ん中に出します。
  - 大きさは、出す画面に収まるように縮めます。

## GitHub のページ

GitHub のページは、既定のブラウザで開きます（リモートが GitHub のときだけ。どのホストを GitHub とみなすかは [architecture.md](architecture.md#github-のボタン)）。

- リポジトリの行の左のアイコン（GitHub のロゴ）にマウスを乗せて少し待つと、すぐ下に、リポジトリ・Issues・Pull requests・Actions のボタンが出ます。「開いているリポジトリ」でも「ほかのリポジトリ」でも、畳んでいても同じです。
  - ボタンは下の行に重ねて出すので、ほかの行は動きません。リポジトリごとにボタンの行を取らないので、一覧が縦に詰まります。
  - アイコンの上を通り過ぎただけでは出ません（0.3 秒乗せたままにすると出ます）。下の行を押そうとして、ボタンを押してしまわないためです。
  - アイコンからもボタンからも離れると消えます。Esc・ほかの場所のクリック・スクロールでも消えます。
  - アイコンをクリックすると、行のほかの場所と同じく、開いたり畳んだりします。
  - 右クリックの「GitHub」からも、同じページを開けます。ペンやタッチで使うときは、こちらを使います。
  - アイコンの右上に赤い点があるリポジトリ（Approve 済みでマージしていない自分の PR がある。[上](#リポジトリ)）では、ボタンの下に「Approve 済み」と、その PR の番号が並びます。押すとその PR を開きます。点はアイコンに重ねてあるだけなので、マウスを乗せたときの動きは変わりません。サイドバーが狭いと、番号は折り返します。
  - GitHub でないと分かっているリポジトリ（GitLab など、リモートのないものも）では出ません。畳んでいても、メインプロセスが読んだリモート（[上](#リポジトリ)の行のアイコンと同じもの）で分かります。初めての起動で、リモートを読み終わる前だけは出ます。
- このブランチの PR: worktree の行の PR の番号（下記）か、worktree の右クリックのメニューから開きます。PR がないブランチでは、行にマウスを乗せると出るブランチのアイコン（「PR を作る」）から、PR の作成画面を開きます。既定のブランチと、ブランチを取り出していない worktree には出ません。

### PR と CI

worktree の行に、そのブランチの PR のアイコンと番号が出ます。色は PR の状態です。

| 状態 | 色 |
| --- | --- |
| ドラフト | 灰色 |
| オープン | 緑 |
| マージ済み | 紫 |
| クローズ | 赤 |

- Approve 済みでマージしていない自分の PR（[上](#リポジトリ)のリポジトリのアイコンの点と同じもの）は、マウスを乗せると「PR #12 オープン・Approve 済み・CI 成功」のように出ます。
- 番号の右に CI の結果が出ます。✓（緑）は成功、×（赤）は失敗、●（黄）は実行中です。
  - オープン（ドラフトを含む）の PR は、PR の最後のコミットの CI です。
  - マージ済みの PR は、マージのコミットの CI（main への push で動いたもの）です。
  - クローズの PR と、CI のない PR には出ません。
- マウスを乗せると、PR の題名と、チェックごとの名前と結果（`CI / Test (windows-latest): 失敗`、`Release / Release (Windows): 実行中` など）が出ます。失敗したものが先に並びます。10 個を超える分は「ほか 3 件」とまとめます。押すと、既定のブラウザで PR を開きます。
- 同じブランチに PR がいくつかあるときは、オープンのものを、なければ一番新しいものを出します。
- PR から作った worktree（[worktrees.md の「PR から作る」](worktrees.md#pr-から作る)）では、作った元の PR を出します。フォークからの PR でも出ます。状態を読むまでと、gh がなくて読めないときは、`#71` と番号だけを出します。
  - リモートのリポジトリにその PR がないとき（あとで origin を別のリポジトリに変えたなど）は、ほかのブランチと同じに、ブランチ名で探した PR を出します。なければ何も出しません。ほかの行の PR には影響しません。
- PR がない行（既定のブランチの行、PR を作っていないブランチ、ブランチのない HEAD）には、worktree の HEAD のコミットの CI の結果だけが出ます。`npm version` と push をした main の行なら、main への push の CI と、タグの push の Release の両方です。
  - マウスを乗せると、コミットの番号と、チェックごとの名前と結果が出ます。押すと、そのコミットのチェックのページを開きます。
  - その行のブランチへの push で動いたものだけを出します。タグの push で動いたもの（リリース）は、既定のブランチの行にだけ出します。main から作ったばかりのブランチは、HEAD が main と同じコミットですが、main の CI は出しません。
  - HEAD を push していない（GitHub にない）ときは、何も出ません。HEAD が進むと、前のコミットで動いている CI は出なくなります。
- マージのコミットと HEAD のコミットの CI は、最後に動いてから（チェックが始まるか終わってから）しばらくだけ出します。成功は 1 時間、失敗と実行中は 1 日です。古いマージ済みの PR の行に ✓ が並び続けたり、pull していない main の行に何日も前の結果が出たりしないようにするためです。オープンの PR の CI は、いつでも出します。
- GitHub でないリポジトリ、gh がない・サインインしていないときは、何も出ません。
- 読み直すのは、リポジトリを展開したとき、worktree のブランチか HEAD が変わったとき、Claude の作業が終わったとき、Worktabs のウィンドウが前に来たとき（前に読んでから 15 秒たっていれば）です。出している CI が実行中のあいだは、1 分おきにも読み直します。
  - Claude が push・PR の作成・マージ・リリースの作成（`git push`、`gh pr create`、`gh pr merge`、`gh release create` など）をすると、その 10 秒後と 30 秒後にも読み直します。push の直後は、GitHub がまだ CI を登録しておらず、読んでも出ないことがあるためです。

## Claude の使用量

サイドバーの下端には、使用量がエージェントごとに分かれて、それぞれの名前を付けて出ます。割合は、Claude も Codex も、残りではなく**使った分**です。各枠は「期間・バー・使用率・↻ リセット時刻」の 1 行です。Claude と Codex の両方で、5 時間と週の枠は同じ表記に揃えます。取得時刻は通常表示には出さず、マウスを乗せたときの詳細で確認できます。幅が狭いと長い時刻は省略しますが、詳細には日時全体を表示します。

- バーは、ふだんはオレンジで、80% からは赤になります。
- 行にマウスを乗せると、リセットされる日時と、いつ受け取った値かが出ます。
- 起動時と 5 分ごとに、会話をしていなくても使用量を取得します。Worktabs のタブの Claude が応答を受け取ったときにも、すぐに更新します。このコンピューターでログインしているアカウントと、拡張に付属する CLI を使い、モデルへメッセージは送りません。
- WSL のタブの Claude からは、まだ受け取りません（WSL のラッパーは claude に置き換わるので、出力を見られません）。使用量はアカウントごとなので、Windows のタブの Claude を使っていれば、その値が出ます。
- 最後の値はデータフォルダの `usage.json` に残します。15 分以上古い値は「不明」になり、リセット時刻を過ぎた枠は取り除きます。Claude が有効なら欄は残り、「更新待ち」「使用量を取得できません」などの状態を表示します。
- 自動取得には Claude の実験的な使用量取得 API を使います。対応しない版、API キーのアカウント、未ログイン、通信失敗では取得できない状態を表示し、次の更新で再試行します。

## Codex の使用量

Codex が有効なら、サイドバーの下端に「Codex · 使用率」も出ます。起動時と 5 分ごとに、このコンピューターでログインしているアカウントの利用枠を取得します。拡張に付属する CLI の app-server に短い間だけつないで読み、会話もモデルのターンも始めません。Windows・macOS・WSL のどのタブでも、拡張からの通知と、読み取りの応答でも更新します。アカウントが変わったときは、もう一度裏で取得します。値を受け取るには、ChatGPT でサインインします。

- 出すのは、知らされた枠だけです。なくてもよい枠が来なくても、空の「第二の枠」の行は作りません。枠の名前は、知らされた長さから「15 分」「5 時間」「週」のように付けます。長さが分からないときは「第一の枠」か「第二の枠」です。利用枠の区分（bucket）の名前は、区分がいくつもあって見分ける必要があるときだけ出します。
- 割合は使った分です。バーは 80% から赤になり、使い切った枠は割合が太字になります。リセット時刻は同じ行に出ます。マウスを乗せると、枠ごとのリセットの日時全体と、受け取った時刻が出ます。
- 利用枠はアカウント全体のものです。タブはどれも同じ利用枠のその時点の値を知らせてくるので、タブごとの割合を足し合わせることはありません。古い問い合わせの答えで、新しく受け取った値を置き換えることはありません。通知はその区分だけを更新し、全体を読んだときは区分の一覧を置き換えます。
- 値が届く前は、下端に「使用量の取得待ち」と出ます。分からない値は 0% ではなくダッシュで出し、同じ行にその状態を出します。リセットのあとは、次の値が届くまで「更新待ち」と出ます。15 分更新がないと、割合は不明になり、「使用量の更新待ち（古い値）」と出ます。
- 裏での取得中や、いつものアカウントの通知が来たときも、取得に成功して置き換わるまで、前の値を出したままにします。取得に失敗したときも前の値を残します。ただし、リセットと 15 分で古くなる決まりは、いつもどおりです。アカウントを確かめ直している間は、同じアカウントだと確かめられるまで、新しく届いた利用枠の値で表示を置き換えません。
- 「使用量を更新中」と出るのは、裏で取得している間だけです。取得に失敗すると「使用量を取得できません」、時間切れになると「使用量の更新がタイムアウトしました」、アカウントや時点の確認で受け付けなかったデータは「使用量の更新を反映できませんでした」と出ます。古い枠が残っていても出ます。これらの状態になっても、古い値を受け取った時刻は変わりません。Codex の見出しか枠にマウスを乗せると、最後に値を受け取った時刻、最後に更新を試みた時刻、次に更新する予定の時刻が出ます。古くなった行で、取得が動いていなければ、その次の試行を待っています。
- 裏での取得は、CLI を探す時間も含めて、1 回 20 秒までです。取得中にアカウントの通知が来ると、その 20 秒の中で、アカウントと利用枠の問い合わせをやり直します。更新の求めが重なったときは、待っている 1 回の再試行にまとめます。失敗しても、5 分ごとのふだんの取得は続きます。
- 使用量が古いままなら、データフォルダの `logs/usage-refresh.log` を見てください。JSON の 1 行ごとに、プロバイダー、試みた時刻と終わった時刻、かかった時間、結果、失敗か受け付けなかった理由の分類、受け付けたアカウントと利用枠のイベントの数、受け付けなかったイベントの数、最後に利用枠を受け取った時刻、次に試みる予定の時刻を残します。これで、取得に失敗したのか、取得はできたが反映できなかったのかを見分けられます。ログには、メールアドレス、アカウントを識別するハッシュ、トークン、アカウントの応答、利用枠のデータそのもの、CLI の生の診断出力は入りません。
- サインアウトしたときや、別のアカウントだと確かめたときは、Codex の値を消します。ログインやログアウトの途中は、下端に「アカウントの確認待ち」と出ます。API キーだけのアカウントでは「API キーでは使用量を取得できません」と出ます。前の値がなくて取得に失敗したときと、取得できても利用枠が空だったときは、「使用量を取得できません」と出ます。
- 下端に出すのは、最後に確認したアカウントの値です。アカウントが変わると、ほかのタブから受け取った値を消します。そのタブは、もう一度アカウントを知らせてくるまで、値に加わりません。どのアカウントか知らされていないときは、使ってよい最新の値から、控えめに出します。サインインしている複数のアカウントを比べる表示ではありません。
- Codex の値は、メモリの中にだけ持ちます。Worktabs を起動し直すと、新しい値を待ちます。トークン、アカウントのメールアドレス、認証の応答全体、クレジット、リセットのクレジットの詳細は、サイドバーに送らず、保存もしません。

## code-server と拡張の更新

「設定 > 拡張」（サイドバーの上端の歯車か、更新のカードの「拡張と更新」から開きます）で、拡張ごとの入手元と版を見て、デスクトップの VS Code の拡張か VSIX ファイルをインポートし、更新を確認できます。Claude は、既定では Open VSX から入れたままです。Codex は、自分で用意したものをインポートして使います。デスクトップからインポートしたものは、ときどき VS Code で更新して、インポートし直す必要があります。VSIX からインポートしたものは、新しいファイルが要ります。ここで確認するのは手元の入手元で、Marketplace 全体の新しい版を知らせるものではありません（[extensions.md](extensions.md)）。更新は、Claude と Codex のターンが終わり、編集が保存されるまで待ちます。Codex がタブで作業中かどうかを Worktabs が確かめられないときは、先にそのタブを閉じるよう、サイドバーに出ます。待機中のインスタンスは、共有している拡張を変える前に止めます。

code-server と拡張（Claude Code と言語パック）は、アプリが勝手には更新しません。新しい版があると、サイドバーの上に「更新があります」が出ます。

- 「更新する」を押すと、まず code-server をダウンロードします。そのあと、作業中・承認待ちのタブや未保存の編集がなくなるのを待ってから更新します。待っている間は「やめる」で取り消せます。ダウンロードとインストールの間は、カードの中で動くバーが、まだ作業中であることを示します。インストーラーは、進み具合の割合を知らせません。
- タブを再起動する前に、新しい版を裏で 1 つ起動して確かめます。ログイン画面にならないこと、フォルダが開くこと、表示が表示言語になること、Claude Code が起動することです。確かめられなければ、元の版に戻します。
- 最後に、起動中のタブを新しい版で再起動します。休止中のタブは、次に開いたときに新しい版で起動します。
- code-server は、ひとつ前の版だけ残します。手で戻すときは、設定ファイルの `codeServerVersion` を前の版にして起動し直します。

版を固定している理由と、更新の中の動きは [architecture.md](architecture.md#更新) にあります。
