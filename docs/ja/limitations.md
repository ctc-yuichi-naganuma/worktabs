# 既知の制限

[English](../limitations.md) | **日本語**

## 動作を確かめた範囲

- 確かめたのは Windows 11 と macOS 26.5（Apple Silicon）です。Intel Mac と Linux では動作を確認していません。
- WSL で確かめたのは、Ubuntu 24.04 で、ネットワークが mirrored（`.wslconfig` の `networkingMode=mirrored`）のときだけです。既定の NAT では、WSL から Windows へつなぐところがないので動くはずですが、まだ確かめていません。
- 未確認の項目: VS Code の diff エディタでの承認。Auto モードでは編集がそのまま通るので、ほとんど出ません。

## Claude Code 拡張

- @-mention でファイル候補が出ません（拡張側の問題 anthropics/claude-code#89933）。
- プロセスラッパーを使うと、拡張は初期の権限モードを CLI に決めさせず、`--permission-mode default`（Manual）を渡します。このためアプリは `claudeCode.initialPermissionMode` に `auto` を設定します（設定の `permissionMode`）。拡張の設定の選択肢に `auto` はありませんが、値はそのまま `--permission-mode auto` として渡ります。
  - この設定は、パネルで選んだモードより優先されます。パネルで切り替えたモードは、その会話の中でだけ有効です。
- タブの再読み込みは、進行中のターン（承認待ちを含む）を中断します。アプリは、作業中なら確認を出します。
- エディタのタブの中で、そのタブの履歴（Session history）から別の会話を選ぶと、前の会話はそのタブの背後に回ります（claude は動いたまま）。拡張はこの会話がどこにあるかを覚えていないので、その行をクリックすると、右のパネルで同じ会話をもう一度開き、claude が 2 つになります。拡張の会話一覧から開いたときも同じです。エディタのタブの「New session」は新しいタブを開くので、この形にはなりません。
- ワークスペースの設定（`.vscode/settings.json`）で `claudeCode.preferredLocation` を決めていると、右のパネルの会話の行をクリックしても、右のパネルを出すだけで、会話は切り替わりません。issue・PR・やることから作った worktree の最初の会話も、右のチャット欄ではなく、その設定の場所に開きます（[architecture.md](architecture.md#補助拡張)）。
- issue・PR・やることから作った worktree のタブでは、claude が 1 つ多く動きます。右のチャット欄が初めて出たときに作る空の会話が、指示を入れた会話の背後に残るためです。拡張にはこれを止める口がありません。空の会話は始めていないので、サイドバーに行は出ません。
- Claude の会話中の `unifiedWindows` は内部用で、自動取得の `get_usage` は実験的な API です。版が変わると取得できなくなることがあります。その場合も欄は残し、取得できない状態を表示します。起動時と 5 分ごとの取得はホスト側のアカウントを使い、WSL だけでログインしたアカウントは対象にしません。Claude・Codex とも Windows の実機で取得を確認しています。macOS のログイン済み環境では、まだ確認していません。
- メインのターンが終わり、バックグラウンドのサブエージェントだけが動いている間は、会話が完了に見えます。サブエージェントがツールを呼ぶと作業中に戻り、会話の行の経過時間も 0 から数え直します。

## Codex 拡張

- 実際に確かめた環境は、[Codex の検証の表](codex-verification.md)にあります。連携を実装して自動テストを通しても、どの OS でも、サインインした状態ですべて動くとは言えません。Windows（ネイティブ）・WSL・macOS のそれぞれで、公式の拡張を使った受け入れの確認が要ります。
- 新しい worktree のやることは、直せる下書きで、自動では送りません。Codex の入力欄に入れられるかは、入れてある拡張の入力欄の形によります。対応していない入力欄や、使用中の入力欄のときは、やることを「タスクをコピー」の付いた警告に残します（[worktrees.md](worktrees.md#作ったあと)）。

- primary 以外の worktree で最初の案内を出さないしくみは、拡張の内部の初回起動用の部品を使います（版 26.1007.21434 で調べたもの）。それより古いか、作りが変わった拡張では、案内が出ることがあります。その場合も、Worktabs は案内をそのまま使えるようにしておきます。primary の案内は、これとは別です（[worktrees.md](worktrees.md)）。Claude の、primary 以外のタブの案内を出さないしくみは、拡張が正式に用意しているユーザー設定 `claudeCode.hideOnboarding` を使います。ワークスペースの設定があると、そちらが優先されることがあります。
- 自動審査は、新しい会話の初期設定です。既存の会話の権限を上書きするものではありません。使っている拡張の、権限の選択メニューを使います。それより古いか、作りが変わった選択メニューは、見分けられないことがあります。そのときは今のモード（ふつうは手動承認）のままにします。実際に効いているモードは、Codex の権限の切り替えで確かめます。使えるかどうかは、アカウントの機能、実行環境の対応、管理ポリシーによります（[config.md](config.md)）。
- 会話の状態を追えるのは、Worktabs のタブの拡張が起動した Codex の app-server だけです。ターミナルやほかのアプリで別に動いている Codex は含みません。
- 拡張に付属する CLI の様子を見るため、アプリはインスタンスごとに `chatgpt.cliExecutable` を設定します。これは拡張の開発用の設定です。ワークスペースの設定で上書きしたり、拡張が変わったりすると、連携が効かなくなるか、壊れることがあります。
- 会話の行をクリックすると、拡張の URI ハンドラーを通して、右のサイドバーの Codex のチャット欄をその会話に移します。ローカルの会話への経路は拡張との連携点で、拡張の更新で変わることがあります。Worktabs は、代わりにエディタのタブで開くことはしません。移れなかったときは警告を出し、右のサイドバーにフォーカスを移そうとします。
- 行が保存されるのは、Worktabs のタブで使ったか再開した会話だけです。Worktabs が保存するのは会話を開くための情報で、会話の中身ではありません。削除されたログや、別の Codex のホームにある会話は戻せません。Worktabs の拡張が止まっている間は、ほかのアプリでのアーカイブや削除を捉えられません。古い行は、開くか隠すまで残ることがあります。
- Codex の使用量は、拡張からの通知と、起動時と 5 分ごとの利用枠の取得から得ます。自動の取得はホスト側のアカウントを使い、WSL だけでログインしたアカウントは対象にしません。取得には、公開されている app-server のプロトコルを使います。ターミナルやほかのアプリで使った分は、次の取得か通知で反映されます。
- API キーだけのアカウントでは、サブスクリプションの利用枠は出ません。データがないときは、不明として扱います。リセットされると割合を消します。15 分報告がないと、古い値として扱い、次の報告が来るまで割合を出しません。
- サイドバーの下端の Codex の欄は、最後に確認したアカウントの値だけを出し、複数のアカウントを同時には出しません。アカウントが変わると、ほかのタブの分も含めて、前の値を消します。どのアカウントか分からない更新は、慎重に扱います。ほかのタブの値は、そのタブがアカウントの状態をもう一度報告するまで使いません。値は、アプリを起動し直すと残りません（[usage.md](usage.md#codex-の使用量)）。

## GitHub

- リモートが GitHub でないリポジトリ（GitLab・Bitbucket・Gitea・社内の Git サーバー、リモートのないもの）では、GitHub のボタン、worktree の行の PR と CI、Approve 済みの PR の点、公開範囲のアイコン、issue・PR からの worktree の追加は使えません。worktree の追加の上の欄は、やることとしてだけ使います（[worktrees.md](worktrees.md#追加)）。リポジトリの行のアイコンは、GitLab と Bitbucket にも出ます。
- GitHub かどうかは、リモートを読んだときに決めて覚えます（[architecture.md](architecture.md#github-のボタン)）。gh で GitHub Enterprise のホストにサインインしたり、`~/.ssh/config` を変えたりしたら、上端の更新ボタンで読み直します。
- SSH の別名は、`ssh -G` で `~/.ssh/config` から読み替えます。git が別の ssh を使うとき（`core.sshCommand`・`GIT_SSH_COMMAND`・PuTTY の plink など）は、その設定は読みません。ssh が別名を知らなければ、URL のホスト名のまま判定します。
- worktree の行に出る PR は、リモート（origin、なければ最初のリモート）のリポジトリの中のブランチから出したものだけです。フォークに push して上流に出した PR は出ません。「このブランチの PR」（`gh pr view`）と同じです。PR から作った worktree だけは、フォークからの PR でも出ます（[worktrees.md](worktrees.md#pr-から作る)）。worktree の削除の確認に出す PR も同じです。
- worktree の削除の確認で、マージ済みの PR にコミットが残っているとみなすのは、ブランチの先頭が PR の最後のコミットと同じときだけです。PR にあとから push されたものを pull していない（ブランチが PR より古い）ときも、コミットは PR にありますが、今までどおり警告します。
- push を拾って少しあとに CI を読み直すのは、Claude が実行したコマンドだけです。VS Code のターミナルや、VS Code の「同期」で push したときは、次の読み直し（Claude の作業が終わる、ウィンドウを前に出すなど）で出ます。GitHub の画面でマージしたときも同じです。
- リポジトリの行の公開範囲のアイコンは、一覧を読み直したとき（起動したとき・更新ボタン・「リポジトリを追加…」のあと）にだけ変わります。GitHub で公開範囲を変えたら、更新ボタンで読み直します。
- CI の結果は、1 つのコミットにつきチェックを 30 個まで読みます。それより多いと、マウスを乗せたときに名前が出ない分があります（「ほか N 件」と数だけ出ます）。

### クローンしていないリポジトリ

- サードパーティのアプリのアクセスを制限している org では、gh の OAuth アプリ（GitHub CLI）が許可されていないと、private のリポジトリが返りません。その org の分は、public のものしか出ません。
- GitHub Enterprise（Server・Cloud）は、試せる環境がないので、gh の答えを模したテストでだけ確かめています。実機では確かめていません。
- 一覧に出すのは、Windows・macOS の gh がサインインしているアカウントの分です。WSL の中の gh だけがサインインしているアカウントの分は出ません。
- 一覧は、一覧を読み直したとき（起動したとき・回る矢印・「リポジトリを追加…」のあと）にだけ GitHub に聞きます。GitHub でリポジトリを作ったら、回る矢印で読み直します。
- 一覧にないフォルダにクローンしたリポジトリ（ghq の並びでないフォルダで、「リポジトリを追加…」していないもの）は、クローン済みと分かりません。
- WSL へのクローンの候補に出るディストリは、`repoSources` で読んでいるものだけです（[wsl.md](wsl.md#クローンする)）。前の版が書き込んだ `"repoSources": ["ghq"]` のままだと、WSL は候補に出ません。
- クローンは、終わるまで止められません（10 分で打ち切ります）。SSH で初めてのホストにつなぐときの「ホストの鍵を受け入れるか」には答えられないので、先にターミナルで `ssh -T git@<ホスト>` を一度実行しておきます。

## VS Code の設定

- Open VSX にない拡張は、発行元の規約が code-server での利用を認めていれば、デスクトップの VS Code か VSIX からインポートできます。これで互換性が保証されるわけではなく、Marketplace を使えるようになるわけでもありません。インポートした拡張は、入手元で更新して、インポートし直す必要があります（[extensions.md](extensions.md)）。WSL へのインポートには、インストール後の確認に失敗したときに自動で元に戻すしくみが、まだありません。

- 同じリポジトリのタブでも、拡張の有効・無効、パネルの配置、コマンドの履歴、拡張がブラウザ側に保存する状態（globalState）は共有しません。VS Code Web は、これらをブラウザの IndexedDB に、オリジン（ポート）ごとに持っているためです。
- WSL に入れるのは、設定にある、アプリが管理する拡張と、対応する Linux 向けのインポートと、補助拡張です。Windows 向けのインポートは WSL にコピーしません。Windows に手で入れた拡張も、WSL では対応する Linux 向けのものを入れる必要があります。

## メモリ

メモリは、実行中のタブ 1 つで約 0.56 GB（code-server）と約 0.24 GB（claude 1 セッション）です。これに Electron 全体の約 0.9〜1 GB が加わります。使っていないタブは休止すると空きます（[usage.md](usage.md#休止と復元)）。

## macOS

- 通知をクリックして会話を開けるのは、アプリが動いている間だけです。アプリを起動し直したあとに通知センターの通知をクリックしても、会話には飛びません（Windows は飛びます。[architecture.md](architecture.md#通知)）。
- サイドバーの右クリックの「Finder で開く」と、VS Code のエクスプローラーの右クリックの「Finder で表示する」は、Windows のようにタブとしてまとめることはしません。
- WSL のタブはありません。
- アプリのメニューは、アプリ・編集・ウィンドウだけです。Cmd+W（VS Code のタブを閉じる）や Cmd+N を VS Code に渡すため、ファイルとウィンドウを閉じる項目は出しません。

## Windows

- エクスプローラーのタブで開く仕組み（`WM_COMMAND 0xA21B`）は、Windows が公開しているものではありません。Windows の更新で使えなくなったときは、新しいウィンドウで開きます。
